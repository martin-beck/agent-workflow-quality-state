# AR-0054: Version-coupled v0.35.0 release follow-up

## Outcome

Publish the AR-0052 bounded TLA+ execution and admission-safety capability as a truthful,
independently reviewed v0.35.0 release without mutating or replacing v0.34.0 or earlier releases.

## Dependency and starting point

- AR-0052 is complete and merged at exact commit
  `fda0517db777b834173253261aca0ba44b28f0f7`.
- Its exact-head Verify `34783047838`, six Portable checks, post-merge Verify `34783382320`,
  and post-merge Portable onboarding `34783382317` are recorded green in AR-0052.
- Begin implementation from that exact merge (after verifying current main and remote state); do
  not reuse a stale pre-merge head or any v0.34.0 release artifact.

## Scope

- Audit and update every version-coupled public declaration from the current version to 0.35.0,
  including package metadata, source constants, lock/catalog projections, compatibility and
  onboarding recipes, contract baselines, generated documentation, release manifests, SBOM and
  provenance fixtures, workflow/release references, and any version-bearing tests.
- Regenerate derived files only through the reviewed generators and ensure their source digests,
  schema versions, artifact identities, and cross-file projections agree.
- Add or update positive and negative tests that reject mixed versions, stale generated output,
  unknown version fields, incorrect release identity, and accidental mutation of prior-release
  fixtures. Preserve native coordinator gates and terminology contracts.
- Use signed conventional commits with an SSH signature and matching DCO trailer. Require an
  independent exact-head diff review covering behavior, public contracts, generated artifacts,
  privacy, formal evidence, and release provenance before publication.
- Publish a reviewed PR only from a clean exact tree; wait for exact-head required CI, merge only
  after all required checks are green, then verify the generated merge commit and exact-main
  Verify/Portable gates.
- Build two deterministic v0.35.0 production bundles under the existing trust policy, compare
  all artifact hashes and canonical metadata, sign the manifest and annotated SSH tag, and publish
  exactly the established six assets (manifest, wheel, sdist, SBOM, provenance, signature).
- Await release/tag attestation and perform fresh public clone, tag, download, hash, signature,
  provenance/SBOM, offline wheel-install, CLI, and authentication/update verification. Record
  exact public URLs, immutable identities, signer/trust evidence, and any environment-limited
  checks without inflating claims.

## Acceptance

- No source, package, fixture, generated catalog, manifest, SBOM, provenance, workflow, or
  documentation version mismatch remains for v0.35.0.
- v0.34.0 and all earlier tags, releases, and assets remain immutable and independently
  verifiable; no old artifact is reused as a v0.35.0 artifact.
- Exact-head review, SSH signatures, matching DCO, privacy scan, formal evidence, generated,
  schema, focused/full applicable tests, and required CI gates pass, with unavailable native
  tooling classified explicitly.
- Two deterministic builds match; the six v0.35.0 assets are signed, attested, externally
  authenticated, and successfully verified from a fresh public clone with offline installation.
- Durable state contains the exact base/head/merge/tag/asset identities, command outcomes,
  attestation and public-verification evidence, plus honest residual limitations before closure.

## Non-goals and safeguards

Do not weaken release, native, formal, privacy, signing, DCO, or exact-head gates; change trust
roots; add runtime dependencies or network acquisition; publish telemetry, credentials, private
paths, host data, prompts, transcripts, or unbounded evidence; alter v0.34.0; or claim full-suite,
native, attestation, or public verification evidence that was not actually obtained.
