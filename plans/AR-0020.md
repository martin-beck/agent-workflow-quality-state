# AR-0020: Pinned Rust stable PR gates

## Outcome

Provide opt-in Rust 1.93.0 contracts for formatting, compiler lint, locked builds,
documentation and tests with deterministic offline execution after reviewed setup.

## Scope

- Pin Rust 1.93.0, Cargo, rustfmt and Clippy components with checksum-verified, bounded, atomic
  Linux x86-64 acquisition outside adapter runtime.
- Add catalog contracts for `cargo fmt --all -- --check`, locked/offline workspace Clippy with
  warnings denied, locked/offline tests, locked/offline documentation with warnings denied, and a
  release build check.
- Require `rust-toolchain.toml`, `Cargo.toml` and `Cargo.lock` as appropriate project-owned inputs.
- Keep Cargo caches and target outputs outside repositories during AWQ fixtures and explain that an
  offline pass assumes dependencies were acquired by a separate reviewed step.
- Add minimal positive crates plus independent format, lint, compile, documentation, lock and test
  failures; compare each adapter result with its native command.
- Normalize tool failure evidence without compiler output, source excerpts, crate names from private
  trees, environment values or machine paths.

## Acceptance

- Exact component probes and every native-equivalence fixture pass on Linux x86-64.
- Missing toolchain/components, version skew, missing manifests/lockfiles, dependency cache misses,
  deadlines and nonzero commands fail with stable content-minimized classifications.
- Runtime argv includes locked/offline controls wherever Cargo resolves dependencies and never
  invokes rustup, installs tools, updates lockfiles, fetches crates or uses a shell.
- Formatting, lint, compilation, docs and tests remain separate evidence and limitations do not
  claim runtime correctness or cross-target portability.
- Full AWQ gates, hosted exact-head/main CI, signed/DCO publication, v0.9.0 release assets and a
  credential-free tagged installer, wheel and native-contract smoke pass.
