# AR-0047: Workflow claims documentation authority and visual evidence

## Outcome

User-visible workflow and documentation claims identify their authority, maturity, semantic tests and reviewed evidence without treating screenshots or file presence as behavioral proof.

## Scope

- Define ordered workflow claims covering goal, preconditions, automatic actions, human decisions, visible outcomes, failures and recovery.
- Map authored, generated, superseded and derived documentation sources to claim IDs and evidence.
- Distinguish `planned`, `contract-tested`, `environment-verified` and `human-reviewed` evidence.
- Add an optional visual evidence contract for exact asset set, digest, dimensions, format, accessibility description, source revision, capture environment class, review and freshness.
- Support consumer-owned API, ABI, form factor, locale and font-scale dimensions without embedding platform pins.

## Acceptance

- Fixtures reject screenshots attached to planned-only behavior, missing semantic tests, orphaned assets, stale/wrong-revision captures, missing accessibility descriptions and contradictory authorities.
- Generated documents cannot replace their declared authority and must bind generator/source digests.
- Visual comparison is deterministic where a consumer supplies baselines, but AWQ makes no human-usability claim from pixel equality.
- Android/JVM evidence can map to the generic contracts without weakening native device gates.
- AWQ performs no screenshot capture, UI execution or external publication.

## Non-goals

Device orchestration, localization correctness, visual approval and end-user usability remain consumer and human-review responsibilities.
