# AR-0045: Formal execution receipts and adapter expansion

## Outcome

AWQ binds formal-tool results to exact sources, models, tools, finite bounds and expected counterexamples, then expands optional execution beyond TLC.

## Scope

- Introduce formal execution receipt v2 with source/model/config/tool digests, run identity, bounds, explored-state or proof-result commitment, outcome, limitations and negative-model expectation.
- Add checksum-pinned, offline-capable Alloy, Kani and Loom adapters in separately reviewable increments.
- Define model mutation and deliberate counterexample evidence so a toolchain that cannot reject a known defect cannot claim useful sensitivity.
- Add implementation-trace correspondence records linking named model operations and states to reviewed production observations.
- Preserve explicit finite-bound, abstraction and non-refinement language.

## Acceptance

- Each adapter has positive, counterexample, timeout, missing/skewed-tool, output-bound and native-equivalence fixtures.
- Wrong model, configuration, tool, bound, source or expected outcome fails closed.
- Deterministic offline tool acquisition/build provenance is verified before execution.
- Trace fixtures reject incomplete operation mappings, reordered events and stronger proof claims than the declared correspondence supports.
- Existing TLC and formal lifecycle/refinement contracts remain compatible or migrate through an explicit versioned path.

## Non-goals

AWQ does not claim unbounded proof, universal implementation refinement or domain correctness outside declared models and bounds.
