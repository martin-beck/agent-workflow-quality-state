# AR-0039: Pinned repository-security adapter family

## Outcome

Consumers can run reviewed offline actionlint, zizmor and introduced-range gitleaks checks through AWQ with pinned identities and bounded, privacy-safe results.

## Scope

- Add checksum-pinned, setup-only installers for supported x86_64 and aarch64 artifacts with atomic publication and exact version probes.
- Define argument-array contracts for actionlint, zizmor pedantic analysis and gitleaks over an exact 40-hex base/head introduced range.
- Ensure runtime uses no network, credentials or ambient configuration and never retains source excerpts, matched secrets or raw subprocess output.
- Normalize findings into stable classifications and digests.
- Add an opt-in repository-security profile connected to AR-0038 trust requirements.

## Acceptance

- Each tool rejects a controlled defect and accepts a clean fixture.
- Tests cover absent/skewed tools, bad checksums, unsupported architecture, invalid or ambiguous history ranges, shallow history, timeouts, oversized output, process descendants and hostile diagnostics.
- Gitleaks proves detection of a secret introduced and later removed within the reviewed range while emitting no secret value.
- Native command equivalence is independently established on controlled fixtures.
- Setup may acquire pinned artifacts; all adapter execution is offline after installation.

## Non-goals

This family does not replace provider-side secret scanning, GitHub security configuration or repository-specific policy review.
