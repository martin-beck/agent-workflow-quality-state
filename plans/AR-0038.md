# AR-0038: GitHub workflow trust policy

## Outcome

AWQ identifies unsafe GitHub Actions trust transitions and distinguishes disposable public-PR execution from privileged or persistent-runner execution.

## Scope

- Introduce a versioned workflow trust policy covering events, repository/ref guards, runner classes, checkout identity, credential persistence, secrets, permissions, reusable workflow inputs and publication boundaries.
- Reject unsafe `pull_request_target` use, unreviewed public code on trusted runners, widened job permissions, caller-controlled privileged inputs, fail-open required gates, unsafe expression interpolation and mutable container images.
- Require exact-head checkout where a gate claims candidate evidence and fail-closed routing where trusted capacity is unavailable.
- Keep project runner labels, protected branches and permitted publication events policy-owned.
- Extend generated explanations so every finding names the trust transition and remediation without source excerpts.

## Acceptance

- Deliberately mutated workflows cover every rule and must fail independently.
- Valid disposable PR, scheduled environmental and guarded manual trusted-runner examples pass.
- Parser behavior remains restricted, bounded and deterministic; unknown workflow constructs fail closed or receive an explicit unsupported classification.
- Existing action-pin, permission and timeout requirements remain intact.
- Privacy tests reject runner names, machine labels and secret-bearing expression values from evidence.

## Non-goals

AWQ does not administer GitHub settings, runners, rulesets, secrets or branch protection.
