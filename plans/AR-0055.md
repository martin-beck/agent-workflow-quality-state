# AR-0055: Register structural-refactoring contract

## Outcome

Integrate the reviewed `structural-refactoring` public contract into AWQ's exhaustive
`contract-catalog-v1` without changing its runtime semantics, weakening catalog gates, or
coupling the catalog to a consumer repository.

## Dependency and starting point

- Depends on AR-0050, whose implementation and focused/full evidence must be reviewed at the
  exact merged revision before this task is promoted.
- Preserve the current contract-catalog implementation and all existing registered entries.
- Do not reuse stale generated files or release artifacts; derive every changed projection from
  the canonical source and record the exact base/head identities.

## Scope

- Add the stable `structural-refactoring` schema entry to the canonical contract-catalog source,
  including its schema path, schema version, lifecycle status, positive/negative/golden fixture
  set, implementation-conformance identifier, fixed focused/full verification argv, and generated
  documentation target required by `contract-catalog-v1`.
- Regenerate `src/awq/data/contract_catalog.json` and all generated catalog/documentation views
  only through the reviewed generators. Update any versioned catalog digest, lock, compatibility,
  onboarding, baseline, SBOM, provenance, or release fixture only when a generator or contract
  dependency proves it is coupled; do not fabricate a release version.
- Add positive and negative catalog fixtures/tests for registration, schema-path confinement,
  stable identifier/version, fixture coverage, implementation mapping, generated-output drift,
  duplicate entries, unknown fields, and accidental omission. Retain the existing intentional
  schema/runtime semantic negative tests from AR-0050.
- Review the complete diff independently, including privacy, source headers, signatures/DCO,
  formal evidence references, native gate and terminology contracts, and exact generated bytes.

## Required gates and handoff

- Focused contract-catalog and structural-refactoring suites, then the complete applicable test
  suite with exact pinned tools and truthful classifications.
- Source-header, Ruff format/lint, mypy, branch-aware coverage floor, catalog and contract-catalog
  `--check`, onboarding/SBOM/provenance/generated documentation checks, assurance-model and
  `validate_contracts` checks, doctor/check, schema/privacy/determinism/diff checks, and all
  applicable native adapter gates.
- Publish only from a clean exact tree in a reviewed PR with an SSH-signed conventional commit
  carrying matching DCO. Wait for exact-head required CI, merge only after green checks, then
  verify exact-main CI and post-merge generated projections. Release work remains a separate
  version-coupled AR and must not be performed here.

## Acceptance

- `generate_contract_catalog.py --check` passes with no unregistered schema and no changed
  existing entry.
- The catalog entry is schema-valid, deterministic, complete, privacy-safe, and visibly mapped to
  AR-0050's exact implementation and fixtures; unknown/duplicate/omitted registration cases fail.
- AR-0050's structural focused suite and complete applicable gates pass; unavailable native tools
  are explicitly classified rather than hidden.
- Durable state records exact base/head/merge/CI identities, independent review, signatures/DCO,
  test/gate results, and residual limitations. No release is published by this AR.

## Non-goals and safeguards

Do not alter structural-refactoring runtime behavior, consumer integrations, native coordinator
gates, terminology requirements, release version, prior releases, trust roots, or catalog gate
strictness. Do not add runtime dependencies, network-required checks, telemetry, credentials,
private paths, host data, prompts, transcripts, or unbounded evidence.
