# AR-0048: Native-binary and runtime-bundle assurance

## Outcome

AWQ verifies complete, offline native-binary and runtime-bundle evidence using consumer-owned policy and external trust roots.

## Scope

- Define optional ELF policy for architecture/class/machine, allowed dynamic dependencies, required hardening, forbidden executable stack/text relocations/features/strings, symbol requirements, alignment and size.
- Define package inventory with exact files, permissions, hashes, targets, licenses/notices, source/toolchain pins and normalized timestamps.
- Bind detached signatures to externally reviewed signer policy and support deterministic second-build manifest comparison.
- Reuse AWQ's bounded non-extracting archive inspection and reject unsafe paths, links, duplicates, irregular members and size/count overruns.
- Acquire readelf, nm and related tools only through checksum-pinned setup; execute offline with discarded output.

## Acceptance

- Positive fixtures cover a minimal reviewed native package and complete runtime bundle.
- Hostile fixtures reject ABI mismatch, forbidden dependency, weak hardening, missing symbol/license, path leakage, incomplete inventory, unsafe archive, wrong target, bad signature and nondeterministic rebuild.
- Provenance binds exact source, toolchain, package and artifact identities.
- Existing AWQ release SBOM and authenticated update behavior remains unchanged.
- Documentation states that bundle verification is not an execution sandbox.

## Non-goals

AWQ does not download runtime components during validation, define product-specific feature policies or authorize execution of verified binaries.
