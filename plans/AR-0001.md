# AR-0001: Bootstrap Agent Workflow Quality

## Outcome

Create and publicly release an immediately usable, versioned quality-policy system for human and
agentic coding workflows, then integrate it in shadow mode with Agent Relay, Agent Relay State,
Agent Systems Benchmark and Agent Systems Benchmark State without extracting coordination logic.

## Scope

- Machine-readable requirement, profile, project-policy, lock, exception and evidence contracts.
- An offline-capable Python 3.12 `awq` CLI with inspect, init, plan, check, explain, evidence,
  policy-diff, doctor and update commands.
- Core, GitHub Actions, Python, shell, documentation, schema, privacy, supply-chain, formal-evidence,
  Rust and Android/JVM profiles with truthful applicability and local extension points.
- Deterministic generated documentation, positive and intentionally broken fixtures, unit/property
  tests, strict typing/linting, branch coverage, secret checks and immutable CI dependencies.
- A pinned release artifact and fresh-checkout installation verification.
- Shadow integrations in all four target repositories. Existing gates remain authoritative until
  equivalence is proved; all handoffctl code, models and task semantics remain out of scope.

## Architecture constraints

- No runtime dependencies, plugins, dynamic code execution, network-required startup, telemetry,
  credentials, machine paths, private evidence or floating versions.
- Unknown profiles, requirements, tools, paths and policy fields fail closed.
- Central updates are opt-in through a reviewable lock diff; a shared release cannot silently alter
  a consumer repository.
- Every requirement declares applicability, tier, determinism, evidence, limitation, remediation,
  exception policy and stable identifier.
- Commands use argument arrays without a shell. Repository paths are normalized, confined and
  symlink-safe. Evidence is bounded, content-minimized and deterministically serialized.

## Delivery sequence

1. Freeze schemas, requirement identifiers, evidence vocabulary and trust tiers.
2. Implement and test the CLI engine, built-in profiles and deterministic generators.
3. Add negative fixture repositories proving mandatory gate families fail.
4. Add self-hosted repository CI, security policy, contributor guidance and generated catalogue.
5. Publish a signed release and verify installation and commands from a fresh checkout.
6. Add pinned shadow integrations to the four target repositories through their own coordination
   and pull-request processes; retain all existing checks.
7. Verify public visibility, PR checks, merge state, privacy, pins and end-to-end consumer output.

## Acceptance

- Every named CLI command has success and hostile-path tests plus stable JSON output.
- `awq init --dry-run` never mutates; explicit initialization produces deterministic pinned files.
- Normal checks run without network access after checkout and reject unclassified tracked formats.
- Requirement/profile/exception/evidence/project/lock schemas reject unknown fields.
- Policy diff identifies weakened enforcement, thresholds, scope, pins and exception expansion.
- At least one negative fixture proves each mandatory shared gate family can fail.
- Documentation is generated from the same requirement registry consumed by the CLI.
- CI passes formatting, lint, strict typing, full branch-aware tests, schema/generation drift,
  dependency integrity, action immutability, secrets, privacy and DCO/signature policy.
- A public immutable release is available and its source/archive digest is recorded.
- All four target repositories execute the exact pinned shared release in shadow mode with no
  project-specific gate removed and no coordination subsystem copied into this repository.
- Fresh public clones of product and state repositories pass their documented verification.
