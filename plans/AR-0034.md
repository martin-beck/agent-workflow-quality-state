# AR-0034: Evidence identity and native-gate correlation v2

## Outcome

AWQ observations share a canonical identity envelope, and native-to-AWQ equivalence can be accepted only when both observations prove that they concern the same reviewed source, inputs, gate definition and execution context.

## Scope

- Introduce a closed, bounded evidence-envelope schema with source commit, tree, reviewed base, gate/config/tool/input digests, run and attempt IDs, evidence class, platform class, collection time and optional freshness policy.
- Version native-gate mappings without changing v1 interpretation. Require v2 pairs to agree on all correlation fields and explain every mismatch deterministically.
- Define `native`, `emulated`, `hosted-portability`, `build-only` and `partial` classifications and prohibit upward inference between them.
- Bind evidence bytes by digest while retaining AWQ's prohibition on command output, host identity, private paths and environment capture.
- Generate documentation and migration guidance for existing v1 consumers.

## Acceptance

- Positive fixtures cover correlated native and AWQ observations at the same exact revision and scope.
- Hostile fixtures reject dirty or changed trees, different bases, tools, definitions, inputs, runs, stale evidence, duplicate keys, unknown fields and partial-to-native promotion.
- Compatibility tests continue to read v1 without silently treating it as v2-quality evidence.
- Consumer-native execution remains authoritative; AWQ validates the mapping and never substitutes for qualification.
- Full schemas, generators, self-hosted checks, privacy review and native-equivalence tests pass offline.

## Non-goals

AWQ will not select hardware, execute private native infrastructure, define consumer platform pins or infer native status from hosted CI.
