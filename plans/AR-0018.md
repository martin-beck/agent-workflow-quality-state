# AR-0018: Pinned Rust assurance profile and adapters

## Outcome

Provide an opt-in Rust profile and reviewed adapter contracts for deterministic formatting,
compiler lint, dependency policy, API compatibility, tests, coverage, fuzzing and mutation without
claiming that any one tool proves runtime correctness.

## Scope

- Pin one supported Rust toolchain and exact offline-capable versions of additional tools.
- Add project-owned contracts for `cargo fmt`, Clippy with warnings denied, tests, Cargo.lock
  integrity, dependency license/advisory/source policy, public API semver checks, coverage, fuzzing
  and mutation testing.
- Separate fast local/PR gates from release, scheduled and trusted-host evidence; never run an
  unbounded fuzzer or mutation campaign in a pull-request contract.
- Require locked/frozen dependency resolution where supported and keep acquisition outside runtime
  adapter execution.
- Normalize failures without compiler output, source excerpts, crate names from private trees,
  environment values or machine paths.
- Preserve a consumer-native command mapping and explicit platform/toolchain limitations for later
  equivalence work.
- Add controlled positive and independently broken crates covering formatting, lint, tests,
  dependency policy, semver, coverage threshold, fuzz seed and mutation-survivor behavior.

## Acceptance

- Every catalog contract has an exact version probe, finite timeout, tier, evidence class,
  limitation, remediation, formats and project-owned configuration paths.
- Adapter and native command outcomes agree on controlled positive and negative fixtures.
- Cargo.lock drift, disallowed dependency policy, public API breakage, lint and test failures are
  rejected by their owning contracts with stable content-minimized findings.
- Coverage reports only measured reachability; fuzz and mutation results state corpus, duration or
  operator bounds and never claim proof.
- Runtime contracts execute offline, do not install/update/fetch dependencies, and do not invoke a
  shell; tool acquisition is checksum-pinned, archive-safe and atomic.
- Linux x86-64 support is verified; target, linker, sanitizer or hardware restrictions are explicit
  rather than inferred.
- Full AWQ gates, hostile installer tests, distribution verification, fresh-wheel smoke, signed PR
  and tag verification, hosted exact-head/main CI, public release assets and credential-free smoke
  all pass.
