# AR-0023: Deterministic release artifacts and manifest

## Outcome

Produce byte-reproducible AWQ wheels and source archives under a documented build contract and bind
each release to a strict canonical manifest that can be checked offline before installation.

## Scope

- Define a strict versioned JSON Schema for a canonical release manifest with reject-unknown
  semantics and deterministic JSON serialization.
- Bind the exact release version, Git source commit and tree, source epoch, Python/build frontend
  versions, immutable build inputs, registry and adapter-catalog digests, artifact names, sizes and
  SHA-256 values.
- Add a bounded release builder that creates wheel and source archives twice in independent
  second-disk scratch roots, compares bytes and archive structure, and fails closed on differences.
- Normalize timestamps, member ordering, permissions, owner metadata, paths and generated metadata;
  never hide an unexplained difference with a post-build rewrite.
- Add an offline verifier for a local release bundle. It must reject traversal, links, duplicates,
  oversized members, undeclared files, digest/size/version skew, mutable references and private or
  machine-specific content.
- Keep signing, SBOM generation and online publication outside this child while defining stable
  manifest extension points consumed by AR-0024 and AR-0025.
- Document the supported reproducibility environment and honest platform/build-tool limitations.

## Acceptance

- Two independent clean builds of the same signed source commit are byte-identical for wheel and
  source archive, or fail with a bounded content-minimized difference classification.
- The manifest is canonical, schema-valid and binds every distributed artifact plus the exact source,
  registry and adapter catalog.
- Positive fixtures verify offline; changed bytes, names, sizes, timestamps, permissions, duplicate
  members, unsafe paths, unknown keys and private path injections fail closed.
- The verifier has no runtime dependency, network access, shell invocation, unbounded input or raw
  subprocess output.
- Full format, lint, type, schema, generation, privacy, hostile-fixture, distribution and clean-tree
  gates pass.
- Signed DCO commit and pull request, exact-head and exact-main hosted CI, signed tag, public release
  assets and credential-free fresh-clone/offline verification all pass.
