# AR-0019: Pinned Android and JVM assurance profile and adapters

## Outcome

Provide an opt-in Android/JVM profile and reviewed adapter contracts for Gradle integrity, source
quality, dependency policy, binary/API compatibility, JVM tests and device-boundary evidence while
keeping network, emulator and hardware assumptions explicit.

## Scope

- Pin supported JDK, Gradle wrapper, Kotlin and Android Gradle Plugin ranges plus exact
  offline-capable auxiliary tool versions.
- Verify wrapper scripts, JAR checksum/distribution URL, dependency verification metadata,
  repository allowlists and lockfiles before executing Gradle tasks.
- Add project-owned contracts for Spotless or equivalent formatting, detekt, Android lint,
  compilation, JVM/unit tests, dependency policy and binary/API compatibility.
- Define instrumentation, UI and accessibility evidence as emulator/device-bound contracts with
  explicit API level, image digest, locale, form factor and timeout; do not imply those checks ran
  from JVM-only evidence.
- Separate local/PR, release, scheduled and trusted-host tiers. Keep acquisition and dependency
  hydration outside runtime adapter execution; run warmed gates offline where tool behavior allows.
- Normalize results without build output, source excerpts, application identifiers from private
  consumers, environment values or machine paths.
- Preserve consumer-native command mappings and add controlled positive and independently broken
  Gradle fixtures for wrapper, verification metadata, format, lint, tests, ABI and UI boundaries.

## Acceptance

- Every catalog contract has an exact version probe, finite timeout, tier, evidence class,
  limitation, remediation, formats and repository-owned configuration paths.
- Adapter and native command outcomes agree on controlled positive and negative JVM fixtures.
- Wrapper tampering, dependency-verification drift, forbidden repositories, lint/test failures and
  binary/API breaks are rejected by their owning contracts with stable content-minimized findings.
- Emulator/device contracts cannot run at an ordinary offline PR tier and clearly distinguish
  configured intent, task success and observed UI/device behavior.
- Runtime contracts do not install SDKs, update wrappers, download dependencies or invoke a shell;
  unavoidable network preparation is a separately authorized, checksum-pinned setup step.
- Supported host OS, CPU architecture, JDK, Gradle, AGP, Kotlin and Android API combinations are
  explicit and mechanically queryable.
- Full AWQ gates, hostile installer tests, distribution verification, fresh-wheel smoke, signed PR
  and tag verification, hosted exact-head/main CI, public release assets and credential-free smoke
  all pass.
