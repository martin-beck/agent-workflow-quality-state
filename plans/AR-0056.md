# AR-0056: Versioned contract-catalog evolution for v0.35

## Outcome

Make the v0.35.0 version-coupled contract projections pass the strict contract-catalog evolution
gate by recording an explicit reviewed evolution from the prior `agent-recipes` contract, while
preserving immutable historical bytes and fail-closed in-place-change detection.

## Dependency and starting point

- Depends on AR-0054's fixture remediation and AR-0035's catalog implementation; do not promote
  until AR-0054's exact candidate head and blocker evidence are reviewed.
- Start from the exact current main and the v0.35.0 candidate's generated projections. Preserve
  the v0.34.0 release, all prior catalog entries, and the runtime contract semantics.

## Scope

- Determine which version-coupled public contracts changed solely because AWQ advanced to v0.35.0
  (`agent-recipes`, compatibility, onboarding, and any linked catalog/baseline projections) and
  classify each as an explicit additive/versioned evolution rather than an in-place mutation.
- Extend the canonical contract-catalog evolution/baseline representation with stable identifiers,
  prior and candidate digests, reviewed version/path identity, rationale, effective version, and
  exact implementation/test mapping. Reject unknown fields, duplicate evolutions, stale source
  digests, path changes, downgrade/replay, and unreviewed in-place replacement.
- Regenerate contract catalog data and generated documentation only through reviewed generators.
  Add positive fixtures for the v0.34→v0.35 evolution and negative fixtures for in-place bytes,
  stale baseline, mismatched version, unknown fields, duplicate identity, and historical release
  mutation. Update lock/baseline/SBOM/provenance only when generator coupling requires it.

## Required gates and handoff

- Run focused catalog/evolution and version/release-boundary suites, then the full applicable suite
  with exact pinned Python/tools. Run source headers, Ruff, mypy, coverage, all generated `--check`
  gates, `validate_contracts`, assurance models, doctor/check, schema/privacy/determinism/diff
  checks, and available native gates with honest classifications.
- Independently review the complete exact diff, signatures/SSH and matching DCO, privacy, formal
  evidence, historical immutability, and release identity before PR publication. Publish/merge only
  after exact-head required CI is green. Versioned release publication remains AR-0054's scope.

## Acceptance

- `generate_contract_catalog.py --check` passes for v0.35.0 without weakening the in-place-change
  rejection rule; all v0.34.0 and earlier catalog/baseline bytes remain unchanged and verifiable.
- Evolution records and generated views are deterministic, schema-valid, complete, privacy-safe,
  and bound to exact prior/candidate digests and reviewed tests.
- Focused and full applicable gates pass; native/tool/cache limitations are explicit and no release
  is published until AR-0054's complete release gates authorize it.
- Durable state records exact base/head/merge/CI identities, independent review, DCO/signatures,
  generated and test evidence, and residual limitations.

## Non-goals and safeguards

Do not weaken catalog strictness, alter runtime behavior, mutate old releases, fabricate provenance,
add runtime/network dependencies, change trust roots, or publish private paths, host data,
credentials, prompts, transcripts, telemetry, or unbounded evidence.
