# AR-0036: Consumer assurance-plan contract

## Outcome

AWQ can determine whether a consumer has declared a complete, owned and reviewable quality plan across its languages and product domains, while leaving execution and domain truth downstream.

## Scope

- Define a repository inventory of languages, build systems, runtime surfaces and quality domains.
- For each gate record a stable ID, owner, invariant, tier, evidence class, bounded argv, input scope, report contract, remediation, limitations and optional native mapping.
- Require each declared domain to have at least one applicable gate or an explicit reviewed unsupported declaration.
- Validate dependency ordering among gates and distinguish shape validation, executed evidence and environmental/native evidence.
- Provide deterministic policy-diff and generated documentation views.

## Acceptance

- Mixed Python, Rust, JVM and documentation fixtures demonstrate complete plans.
- Negative fixtures reject orphaned domains, duplicate invariants, missing ownership, shell strings, overlapping identifiers, unknown report contracts, circular gate ordering, stale observations and unsupported declarations without rationale.
- Exact-revision observations use AR-0034 identities; declarations alone cannot appear as passing evidence.
- Consumer commands are never executed by plan validation.
- Agent Relay and Agent Systems Benchmark can express their current assurance inventories without weakening native gates or importing coordinator behavior.

## Non-goals

AWQ does not decide which domain tests a product needs, schedule workers, or replace repository-specific full gates.
