# AR-0035: Public contract catalog and evolution gate

## Outcome

Every public AWQ schema and contract is discoverable through one generated, machine-readable catalog with explicit fixtures, implementation conformance and compatibility history.

## Scope

- Define a closed `contract-catalog-v1` schema listing stable contract ID, versioned path, status, positive and hostile fixtures, implementation-conformance ID, fixed test argv and generated documentation target.
- Discover public contract files and fail on unregistered or duplicate entries, orphaned fixtures, missing tests and stale generated documentation.
- Compare published schema bytes and reviewed semantic summaries against an exact baseline. Incompatible edits require a new versioned contract path; compatible changes require explicit classification.
- Verify that each registered command is an argument array, bounded, offline-capable and mapped to a real test or self-host gate.
- Generate a human review table from the catalog rather than maintaining a second authority manually.

## Acceptance

- The initial catalog covers all shipped schemas and externally consumed structured contracts.
- Fixtures prove missing registration, duplicate IDs, missing positive/negative coverage, unknown fields, command drift, removed conformance handlers and in-place incompatible edits fail closed.
- Catalog ordering and generated output are deterministic across clean builds.
- Historical release fixtures remain readable at their declared versions.
- No catalog entry can claim semantic execution merely because a schema or file exists.

## Non-goals

The catalog does not execute consumer-native gates or make backward compatibility claims not established by explicit tests.
