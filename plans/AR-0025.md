# AR-0025: Signed provenance, trust roots and verified updates

## Outcome

Let an agent verify who authorized a release, which workflow and source produced it, and every local
bundle artifact before AWQ changes a consumer lock.

## Scope

- Define a strict canonical SLSA-compatible provenance predicate binding builder/workflow identity,
  exact source commit, invocation/build recipe, materials, subjects, manifest and SPDX SBOM.
- Publish provenance and an authenticated release-manifest signature or attestation using pinned
  GitHub Actions and immutable action commits; distinguish hosted environmental evidence from
  offline cryptographic verification.
- Define independently provisioned trust roots, expected signer fingerprints and explicit
  add-overlap-retire rotation with rollback protection. Never bootstrap trust solely from the clone
  or release bundle being verified.
- Document and test the non-persistent SSH tag-verification command using config/allowed_signers,
  including independent fingerprint comparison and signer-principal binding.
- Extend update handling so acquisition is explicit and separate: given a local candidate bundle and
  external trust policy, verify tag/source, manifest, artifacts, SBOM, provenance, version monotonicity
  and registry/catalog bindings before atomically changing quality/awq.lock.json.
- Refuse downgrades, equivocation, expired/unknown/removed signers, unsigned or mismatched subjects,
  mutable refs, partial bundles, unknown fields, symlinks, unsafe paths and private evidence.
- Keep verification bounded, argument-array based, content-minimized and offline after the candidate
  bundle and trust roots have been acquired.

## Acceptance

- A clean credential-free clone verifies a release tag only when an independently provisioned trust
  root authorizes the exact principal/key fingerprint; clone-local trust alone is clearly rejected
  as insufficient.
- Provenance subjects match every manifest artifact and the SBOM; source/material/workflow identity
  mismatches and mutable references fail closed.
- A consumer dry-run reports the exact reviewed lock diff without mutation; a verified update changes
  only the canonical lock atomically, while every failed verification leaves it byte-identical.
- Key rotation succeeds only through an authenticated overlap and rejects removal of the last valid
  root, rollback and conflicting signer histories.
- Hosted attestations and offline signatures have explicit, tested proof boundaries and do not claim
  a SLSA level merely because provenance exists.
- Full positive/negative, privacy, reproducibility, distribution, signed PR/tag, exact-head/main CI,
  public release and credential-free offline fresh-clone verification gates pass.
