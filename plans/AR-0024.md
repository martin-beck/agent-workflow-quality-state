# AR-0024: Canonical SPDX SBOM and license inventory

## Outcome

Ship a deterministic, standards-traceable SPDX software bill of materials for every AWQ release,
covering the project, distributed artifacts and locked build inputs without overstating completeness.

## Scope

- Select one exact SPDX specification edition and canonical JSON serialization supported by an
  authoritative validation source; record the edition and limitations in the control catalogue.
- Generate package, file/artifact, checksum, license, supplier/origin and relationship records from
  the signed source tree, project metadata and uv.lock without network resolution.
- Distinguish zero runtime dependencies from build, development and bundled-tool acquisition inputs;
  do not imply that separately downloaded adapter tools are contained in the AWQ wheel.
- Use stable SPDX identifiers and namespaces derived from public release identity, never host paths,
  usernames, timestamps from wall clock, credentials or private consumer names.
- Bind the SBOM name, size, digest, format and SPDX edition into the AR-0023 release manifest.
- Add strict structural and semantic validation, canonical regeneration checks and hostile fixtures
  for omitted packages, wrong relationships, invalid licenses, digest skew, unknown fields and
  private-data leakage.
- Document what the SBOM proves, what remains external, and how agents inspect it offline.

## Acceptance

- Regeneration from the same signed source and lock is byte-identical and passes the pinned SPDX
  validation contract.
- The SBOM names the AWQ package, wheel, source archive and all locked build/development packages
  with correct scopes, checksums where available, licenses and relationships.
- Runtime-dependency claims agree mechanically with wheel metadata and cannot silently omit a
  dependency or classify a build tool as shipped runtime content.
- Manifest-to-SBOM and SBOM-to-artifact/source bindings fail on any identity, size, digest, version,
  namespace or relationship mismatch.
- Unknown, duplicate, oversized, noncanonical or privacy-bearing data fails closed with bounded
  findings and no network or shell execution.
- Full gates, signed PR/tag, exact-head/main CI, public release assets and credential-free offline
  fresh-clone verification pass.
